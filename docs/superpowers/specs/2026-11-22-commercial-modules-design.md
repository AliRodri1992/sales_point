# Commercial modules — approved development direction

Baseline: `feature/fixes`, `4a5f0c45073d9772227625b749309f94da16516a`. Scope: existing `/admin/promotions` and `/admin/price_lists`, their commercial pricing boundary, and their sidebar entries. Do not change protected branches or implement checkout, inventory or accounting internals here.

## Design

Separate Products, Price Lists and Promotions. Use a Commercial sidebar group, independent Pundit permissions and breadcrumbs. Products retain their quote and read-only commercial references. Reuse the established Rails models and services rather than create a second pricing engine; split generic views into dedicated screens. Do not change the existing Delta Emerald design system or add dependencies.

### Interaction contract

- Tailwind CSS 4, responsive layouts, existing Delta Emerald tokens, ViewComponent/ERB, Hotwire and Stimulus; original inline SVG with `currentColor`, no icon library or CDN. Locale keys in es/en/ko. Use the existing `delta-select` (no internal radios, selected emerald/white), search for long catalogs, no search for short enums. Keyboard, focus, ARIA, busy/empty/error and 422 recovery.
- Lists: searchable name/code, effective status, advanced filters (currency, segment, included product, validity); price-list table with product count and date range. Promotions: campaign name/code, benefit, audience, validity, usage and state; advanced filters by benefit, product, category, segment, validity and usage availability. Removable filter chips, reset, URL persistence, pagination and ordering; use allowlisted sort, direction and filter values.
- Create/edit: generated immutable organization-scoped `LP-000001`/`PRO-000001`; retain historical codes. Currency defaults to organization base; select active catalog currencies through searchable `delta-select`; immutable after create. Dates use the organization's zone. Use field-specific server validation.
- Price List editor: search active tenant products by name/SKU/barcode; a result click adds a row instantly. Columns product/options, base price, list price, margin, remove (after margin). Respect variants, presentations and row validity. Never silently remove historical price changes: draft rows may be removed, persisted rows retire/version without destroying financial references. Show detail in read-only mode with price, margin, status, segment, validity and price change history. Margin is `(price-cost)/price`; unavailable for zero price, unknown cost or different currencies. Require reason for historical price changes and explicit authorization for below-cost prices.
- Promotion editor: top-level general, benefit, conditions, validity and usage sections, no unnecessary nested cards. Search and select products/categories with removable selections. Show detail in campaign layout with benefit, usage, eligibility, dates and history. Editable forms retain valid historical associations; new associations must be active, not retired and in the organization.

## Commercial behavior

- Persist draft, active, paused, archived. Effective state priority: archived/draft/paused; expired (end exclusive); scheduled (start inclusive); exhausted (global limit only); active. Transition actions enforce server authorization, transaction, state validity, confirmation and audit; no arbitrary status dropdown. Archived is terminal, expired/exhausted are consult/duplicate/archive; allow valid activation or resumption only. Scheduled and active may pause. Draft requires a benefit or list item before activation. Duplicate produces draft with new code, no history or redemptions.
- Price resolution: explicit eligible price list; in future support assigned customer/segment/default list with deterministic priority and overlap detection. Use price matching product/variant/presentation and effective row; base fallback only in the same currency, never implicit currency conversion. Promotions apply after list price; default best single discount, deterministic tie, no stacking unless explicit. Exclusive rules and controlled sequential accumulation have to be designed as explicit compatible modes; preserve existing line-quote result until multi-benefit APIs are versioned.
- Product OR product within a condition kind; category OR category; AND between different kinds to retain the existing intersection semantics. Minimum quantity in base units, minimum subtotal on line in current engine; whole-cart promotions must use an explicit new cart-level contract, not pretend line totals are cart totals. Exclusions override inclusion. Prevent invalid/retired/foreign targets, including legacy global categories (PROMOTIONS-001). Limits per customer require identity; total quota checked transactionally at redemption, not consumed by preview. No negative total; decimal precision according to currency. Preserve immutable redemption snapshots, idempotency and original prices for downstream returns.
- Further commercial scope to sequence behind foundational screens and domain tests: default/assigned lists, volume tiers, minimum margins, exclusions, priority conflicts, explicit promotion combination rules, maximum discount, hours/schedule, list targeting, branch scope and formulas. Keep advanced features disabled unless supported and tested. Checkout-level approvals/discounts, return calculation, coupons, loyalty, bulk import/export and reports are separate integration phases; no misleading controls for unsupported functionality.

## Authorization and acceptance

Own access/index/show/create/update/archive, activate/pause/resume/duplicate, history and margin-view permissions; migrate existing product-read grants conservatively, never turn existing non-admin product-write rights into commercial write rights. Reuse policies, tenant scopes and audit patterns. Cost/margin data is sensitive, including JSON and HTML data attributes. Verify IDOR, malformed parameters, concurrent allocations/redemptions and 422 with retained input. Reuse `Products::Quote`, `Products::SavePriceList`, `Products::RedeemPromotion`. Simulator uses non-mutating quote. Preserve old contracts and existing specs, update intentional behavior tests together.

Quality: maintain module records `docs/quality/modules/{promotions,price-lists}.md` and permanent IDs; no new top-level resource needed. Test desktop/mobile 320/390/768/1440, keyboard/focus, zoom 200%, translations and accessibility. GitHub Actions on the exact `feature/fixes` SHA is the requested validation environment (local Ruby and Docker unavailable). Never claim verification until actual RSpec and RuboCop results are green; report other CI results separately.
